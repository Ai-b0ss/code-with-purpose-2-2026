# Музейный компас — ГИМ

Уточнение: в новой таблице Евы на 15 строк только 9 кандидатов и 9 карточек ожиданий. Состав целевых 15 анкет нужно сверить по ID. [Разбор](docs/18-criteria-source-audit-20261021.md).

Актуальная сверка источников и кода: [критерии, вопросы и требования](docs/18-criteria-source-audit-20261021.md), main `7d8ece8`, Илья `26aa964`, Александр `ef311e8`. Ниже сохранены результаты прежних прогонов с их датами; новые ветки не считаются интегрированными. Пять групп критериев уже есть в оригинальном DOCX музея. Оценка/ранжирование, LLM-уточнения внутри формы и совокупная аналитика остаются незавершёнными требованиями.

**Хакатон ВШЭ «Код со смыслом 2» · 21–22 октября 2026 · Государственный исторический музей**

Веб-анкета для кандидатов в волонтёры ГИМ: вопросы и уточнения → подтверждение кандидату → сохранение ответов и внутренней рекомендации → выгрузка для координатора. Целевое время заполнения — **5–7 минут**, реальный замер командой ещё нужен.

**Исправление конкурирующих повторов ID ([PR #39](https://github.com/Ai-b0ss/code-with-purpose-2-2026/pull/39), уже в `main`):** SQLite резервирует ID до запуска медленного оценщика. Одновременные запросы с одним ID используют один сохранённый результат, разные ID не ждут друг друга из-за открытой транзакции. Пропавшая модель освобождает резерв; брошенная при остановке сервера запись может быть перехвачена после 10 минут. Второй запрос при слишком долгом ожидании получает 409 с Retry-After, а не серверную ошибку 500. Это гарантия одной строки SQLite, не гарантия exactly-once платного вызова через рестарт процесса. [Детали и тесты](docs/19-sqlite-reservation-20261021.md).

**Исправление вопросов [PR #38](https://github.com/Ai-b0ss/code-with-purpose-2-2026/pull/38):** не более 2 приоритетных вопросов для собеседования и 3 уточнений в форме. Непроверенное расписание фондов и норматив 8–12 часов удалены из формулировок. **Регрессия после [PR #39](https://github.com/Ai-b0ss/code-with-purpose-2-2026/pull/39):** 54 pytest PASS / 1 live SKIP и 73 локальные smoke-проверки PASS / 1 SKIP. Вызов живой модели после этих изменений не запускался.

## Запуск ReformBoss (настоящая LLM)

Добавлен [`start-reformboss.ps1`](start-reformboss.ps1): по умолчанию проверяет `deepseek-v4.1-flash` через `https://api.reformboss.com/v1/chat/completions` на вымышленном кандидате, затем поднимает приложение в режиме `llm`. Ключ запрашивается **видимым вводом** (не показывайте экран во время ввода) и не записывается на диск.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-reformboss.ps1
```

`-TimeoutSeconds 180` — таймаут запроса к провайдеру (по умолчанию 180, диапазон 1–300 с); `-SkipProbe` — запустить без повторного LLM-пробника; `-Port 8766` — выбрать желаемый начальный порт (по умолчанию 8765 с автопереходом на следующий свободный); `-Model glm-5.3` — переключить модель; `-Compare` — три реальные API-вызова для DeepSeek, GLM и Kimi; `-DisableJsonMode` — обход несовместимого `response_format`. Живой запрос к `deepseek-v4.1-flash` **успешен (37,8 с; валидный JSON, 12 evidence, score=null и риск первого курса отражён)**. Старый порт `8765` оказался занят; [PR #26](https://github.com/Ai-b0ss/code-with-purpose-2-2026/pull/26) добавил автоматический поиск свободного порта. Чтобы не повторять долгий вызов при запуске, используйте `-SkipProbe`. [Инструкция](docs/11-llm-evaluator.md).

## Запуск на своём ноутбуке

Нужны Git и Python 3.11+.

```powershell
git clone https://github.com/Ai-b0ss/code-with-purpose-2-2026.git
cd code-with-purpose-2-2026
python -m pip install -r requirements.txt
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8765
```

На Windows можно запустить `run.bat`. Откройте **http://127.0.0.1:8765** *на том же компьютере*. Установка и запуск тестов одной командой в Windows — `run-tests.bat`. Эти тесты не требуют GitHub Actions или платных ключей.

**По умолчанию `rules_demo`.** Чтобы попробовать настоящую совместимую LLM, нужно отдельно настроить `GIM_EVALUATION_MODE=llm`, `GIM_LLM_ENDPOINT` (полный URL `/v1/chat/completions`) и `GIM_LLM_MODEL`; ключ `GIM_LLM_API_KEY` необязателен для локальной модели. Ненастроенную модель не считать активной. [Подробная настройка](docs/11-llm-evaluator.md).
