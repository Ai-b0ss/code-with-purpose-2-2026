## 3. Проверка оценщика: 4 кандидата

Ветка содержит `tests/test_availability_policy.py` и `backend/availability_policy.py`. Эти правила обеспечивают отрицательные **сигналы** доступности, не официальный балл 0–3.

| Кандидат | Ожидаемый вывод |
| --- | --- |
| **А. Первый курс**, мотивирован, 20 часов, субботы | Первый курс — исходный **минус** для долгосрочной доступности; устойчивые субботы — возможное исключение, надо проверить сессию и план |
| **Б. Полная ставка**, 20 часов, свободные выходные | Полная ставка — **минус** по нагрузке; подтверждённые регулярные смены могут смягчить |
| **В. Три других проекта**, для ГИМ 4 часа | Явный риск перегрузки и раннего ухода; запросить приоритет и реальный график |
| **Г. Третий курс**, 24 часа, стабильные субботы | Не приписывать риски первого курса / полной ставки |

- [ ] Для А/Б/В отрицательные факторы отражены в `possible_problems` и `fit_for_museum`.
- [ ] Индивидуальные исключения учтены, но не стирают исходные риски.
- [ ] Кандидату Г не приписана несуществующая перегрузка.
- [ ] Отдельно объяснены `fit_for_museum` и `fit_for_candidate`.
- [ ] Все цитаты-основания действительно содержатся в анкете, факты не выдуманы.
- [ ] Балл `score` остаётся `null` до реальной калибровки.

**Ограничение:** маршруты FastAPI пока вызывают `evaluate_demo()`; самостоятельный LLM-оценщик **не подключён к UI/API**, настоящий вызов модели **не проверен**. Ни один mock-тест не равен проверке live-LLM.
