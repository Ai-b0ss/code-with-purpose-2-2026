# Музейный компас — тестовая сборка команды с пилотной оценкой (22.10.2026)

Это **переносной ZIP, не exe и не публичный сервис**. Windows 10/11 и Python 3.11+ обязательны. Git, GitHub-токен, права администратора не нужны. Интернет нужен для первой установки Python-пакетов и каждого запроса к DeepSeek через ReformBoss.

## Запуск

1. Распаковать ZIP целиком в свою папку, не запускать напрямую из архива.
2. Дважды нажать **START-TEAM.cmd** (или запустить `powershell -NoProfile -ExecutionPolicy Bypass -File .\team-start.ps1`). Первый запуск создаёт локальную `.venv` и скачивает зависимости.
3. Дождаться запроса ключа; **ввести ReformBoss API-ключ** без префикса Bearer. Ввод **видимый**, поэтому не включать запись экрана и не отправлять скриншоты консоли. Ключ не записывается в файл. Он находится в переменных окружения процесса и очищается при завершении команды.
4. В консоли появится `http://127.0.0.1:8876` (при занятом порте ближайший свободный). Открыть его в браузере **того же ноутбука**, не закрывая консоль. Открывать через интернет/туннель пока запрещено.
5. Заполнить **вымышленную** исходную анкету. При переходе на шаг 4 DeepSeek сначала изучит 5 критериев и при существенной неопределённости задаст **до двух вопросов самому кандидату**; после ответов возможен ещё один новый вопрос при важном противоречии (не более трёх за анкету). Ответьте на них (допустимо «Пока не знаю»); только затем нажмите «Отправить», после чего DeepSeek проведёт **повторный анализ с учётом ответов**, сохранит балл и предварительный вердикт для куратора. Обычно это два обращения к LLM, либо три при повторной проверке уточнений. При нарушении формата каждый этап делает максимум один запрос исправления в пределах своего таймаута 180 секунд. Это расходует лимит провайдера. Остановка сервера — Ctrl+C.

При запуске **нет предварительного платного LLM-пробника**. В /api/v1/health должно быть `evaluation_mode=llm`, `fallback_to_demo=false`; это проверка конфигурации, **не доказательство доступности модели**. Настоящая проверка — успешная отправка вымышленной анкеты с `evaluation_mode=llm` и непустыми `evidence`.

## Что смотреть

- **Ожидание ИИ:** на финальной отправке виден индикатор; кнопки Назад и Отправить неактивны до ответа. Если ИИ задаёт дополнительный вопрос, индикатор снимается, и кандидат отвечает. Ограничение в две минуты не обещается: анализ состоит из отдельных обращений.
- **VK:** перед долгим обращением бот сообщает о проверке; после сбоя отправки предлагает Повторить отправку с прежним ID, не пропуская обязательные уточнения. Timeout VK по умолчанию 210 секунд.
- **Форма**: четыре шага, в настоящем LLM-режиме **до двух вопросов по выявленным пробелам и ещё один новый вопрос после ответов при необходимости**, заданные ДО отправки; отсутствие пробелов означает 0 вопросов. В `rules_demo` остаются прежние правила (до 3 вопросов). Выбранное направление сохраняется.
- **Оценщик**: повторно учитывает ответы на уточнения, даёт оценки по 5 критериям, `preliminary_verdict`, `verdict_comment`, сильные стороны, риски, рекомендуемое направление. Уточнения задаются кандидату ДО заключения. Дополнительно `interview_focus` содержит до двух тем для куратора на очном интервью. `CURATOR-REPORT.cmd` показывает вопросы, ответы и результаты из локальной SQLite.
- **Пилотная оценка 0–3**: в режиме реальной LLM DeepSeek возвращает пять оценок `scorecard` с аргументами и полями-доказательствами; сервер вычисляет предварительный `score`, `score_status=pilot_unvalidated`. Если доказательств мало — `score=null`, `score_status=insufficient_evidence`. **Это не статистически калиброванная шкала и не решение о приёме**, ранжирование для решения куратора не реализовано. В `rules_demo` балла нет.
- **QA-4-CASES.cmd**: четыре встроенных синтетических сценария. **Каждый вызовет реальный LLM API** и может расходовать лимиты/деньги. Проще начать с одной анкеты, а потом запускать полный QA.
- **CSV**: данные сохраняются локально в SQLite, экспорт существует в API. После настройки Google-доступа строки автоматически отправляются в Google Sheets; без настройки остаются в SQLite со статусом google_not_configured.

## Ограничения и защита

Это локальная тестовая версия **только для синтетических данных**. API списка анкет, карточек и экспорта **не закрыт авторизацией** (#28). Не открывать сервер на 0.0.0.0 и не публиковать через туннель. Устанавливать только на доверенных ноутбуках. При передаче ZIP проверить SHA256 в GitHub/манифесте и не добавлять приватные анкеты/ключи.

Новый ZIP содержит исправления ветки `codex/fix-agent-contract-and-curator` от `main` 648af50: контракт модели, два раунда уточнений, карточку куратора и VK-бота. Папки `data`, `reports`, история Git, приватные таблицы, DOCX, API-ключи, `.env` и `.venv` не включаются. Документы требований внутри архива — только текстовые файлы; исходные материалы и экспертные таблицы доступны ответственным участникам отдельно.

**Проверки проекта:** pytest и локальный FastAPI smoke (точные результаты в `docs/19-sqlite-reservation-20261021.md`). Исправленная версия прошла 22/22 настоящих сценария ReformBoss: все итоги сохранены; девять повторных и парных анкет дали одинаковые пять оценок. Точная сводка в `docs/23-agent-contract-and-vk-fix-20261022.md`. Технический PASS не заменяет экспертную оценку Евы и уточнение числовой рубрики 0–3.

Документы: `docs/04-gim-requirements.md`, `docs/06-gim-stakeholder-answers.md`, `docs/18-criteria-source-audit-20261021.md`, `docs/09-delivery-roadmap.md`, `docs/20-gim-scoring-pilot-20261022.md`, `docs/21-ai-clarification-before-verdict-20261022.md`. ## Если не запускается

Python не найден или версия ниже 3.11 → установить Python 3.11+ и запустить снова. Ошибка pip → проверить доступ к PyPI. TLS/network preflight → проверить сеть, ключ ещё не запрашивался. HTTP 401 → ключ неверный/не принимается. HTTP 429 → лимит провайдера. 503/timeout → ответ LLM не получен за таймаут. Порт занят → скрипт выберет другой из 8876–8896. Данные `data/` не стирать при повторном запуске.
