# ГИМ: вопросы до итоговой оценки — сквозной сценарий (22.10.2026)

**Источники:** исходная анкета ГИМ, разделы о критериях и дополнительных
вопросах; текст выступления заказчика (06:27, 07:41, 08:45); актуальная
[сверка исходников](18-criteria-source-audit-20261021.md). Эти источники
требуют контекстных уточнений и оценивания, но не утверждают числовой лимит
или конкретную LLM-архитектуру.

## Исправление предыдущей ошибки

До исправления четвёртый шаг формы делал POST `/api/v1/clarification`,
получая **фиксированные Python-правила** (например, длина ответа менее
65 знаков). DeepSeek запускался лишь при POST `/api/v1/applications`
и возвращал `interview_questions` уже **после** регистрации анкеты.
Эти вопросы не задавались кандидату и не меняли оценку.

## Реальный порядок в версии с исправлением

1. Кандидат заполняет исходную анкету (личные данные, мотивация/опыт,
   интерес, направление, нагрузка). Подтверждает согласие на обработку.
2. На переходе с шага 3 на шаг 4 выполняется POST `/api/v1/clarification`.
   В `GIM_EVALUATION_MODE=llm` DeepSeek изучает все **пять критериев**
   исходного кейса и возвращает `criteria_review`: по каждому
   `clear`, `uncertain` или `risk` с краткой причиной.
3. При существенной неопределённости ИИ выдаёт **0–2 вопроса КАНДИДАТУ**
   с объяснением `reason` и влиянием на решение `decision_impact`.
   Уже известные данные не переспрашиваются. При полной ясности
   `questions=[]`. Вопросы на форме не для будущего интервью:
   кандидат отвечает **сейчас**, до отправки.
4. Пока не даны ответы на возникшие вопросы, форма не отправляет заявку;
   допустимый ответ — «Пока не знаю», это неопределённость, а не ложный
   отрицательный балл. В локально сохраняемой заявке доступны
   `followup_questions` (исходный текст вопросов), `followup_answers`
   (ответы), `followup_answer` (старое совместимое поле).
   Изменение базовой анкеты инвалидирует прежние уточнения.
5. После отправки вызывается **новая** полная оценка DeepSeek на
   исходных и дополнительных ответах. Результат: пять уровней
   `scorecard`, ссылки на `evidence`, предварительный `score` 0–3
   или `null`, риски, сильные стороны, саммари, обоснованное
   `recommended_direction`, `preliminary_verdict` и
   `verdict_comment` для координатора.
6. `preliminary_verdict` принимает
   `suggest_interview` / `manual_review` / `not_recommended_for_interview` /
   `insufficient_information`. `not_recommended_for_interview` используется
   только при прямо подтверждённом несоответствии задачам, не для
   автоматического отказа по году обучения или частичной занятости.
   **Это предварительная рекомендация о дальнейшем рассмотрении,
   не автоматическое принятие или отклонение.**
   Вычисляемый равновесный балл в пилотной шкале не откалиброван
   по историческим оценкам.
7. Кандидат видит подтверждение, а не внутренние баллы. Куратор
   смотрит локальный `scripts/launchers/CURATOR-REPORT.cmd` с критериями, вопросами,
   ответами, комментарием, рекомендацией и рисками.

## Контракты и надёжность

- Live-режим требует корректный ответ DeepSeek на оба этапа. При
  ошибке предварительного анализа API возвращает 503, форма сохраняет
  черновик и не подменяет ИИ детерминированными «случайными» вопросами.
- В явном `demo` используется прежний набор правил без API и без
  подмены реального режима.
- Код передаёт в модель для предварительного вопроса только ответы
  без ФИО, даты рождения, email и VK. Модель может получить
  остальные сведения анкеты; нужны согласие и адекватная защита ПД.
- Формат `interview_questions` остаётся для старой базы и
  совместимости. В **новой финальной генерации** модель инструктирована
  вернуть пустой список: вопросы задаются до финала, а остаточные
  проблемы попадают в verdict_comment и possible_problems.
- Два модельных вызова вместо одного увеличивают время/стоимость.
  Автоматического fallback в demo при ошибке нет.
- Не использовать реальные ПД без закрытия доступа к API (#28).
- Точность итогового скоринга по независимым данным и полнота
  вопросов требуют экспертной проверки (#27).

## Приёмка

- Полная анкета с неопределённым графиком: LLM предварительно
  возвращает вопрос о конкретных днях; ответ сохраняется, попадает
  в окончательный контекст и влияет на интерпретацию риска.
- Полная анкета без пробелов: ноль дополнительных вопросов,
  финальный разбор и предварительный вердикт доступны.
- При двойном обращении после окончательной отправки сохраняется
  одна заявка; прежняя SQLite-защита ID остаётся.
- Ошибка LLM до финала: честная ошибка, отсутствие записи
  в SQLite и возможность повторить.
- Независимая оценка Евы по новым анкетам и точность DeepSeek
  с реальным ключом ещё отдельно не подтверждены.
