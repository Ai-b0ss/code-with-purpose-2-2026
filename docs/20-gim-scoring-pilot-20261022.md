# ГИМ — предварительная рубрика 0–3 (pilot-v1, 22.10.2026)

Этот документ описывает прежний вариант, где уровни пяти критериев возвращала
модель. Текущая реализация рассчитывает уровни на сервере из проверенных
категорий полей; см. `docs/23-evaluation-harness-20261022.md`.

**Статус:** инженерная рабочая гипотеза. Это НЕ официально утверждённая ГИМ шкала,
НЕ статистически откалиброванная модель и НЕ автоматическое решение о приёме.
До любого отбора куратор должен прочитать исходные ответы, проверить evidence,
учесть индивидуальные обстоятельства и подтвердить оценку. Настоящие персональные
данные не использовать в открытой тестовой версии (#28).

## Происхождение

Пять направлений критериев буквально происходят из раздела 3 оригинальной
«Анкеты волонтера. Вопросы..docx», а уточнения по нагрузке записаны по итогам
общения команды с заказчиком. См. [проверенные исходники](18-criteria-source-audit-20261021.md),
[требования](04-gim-requirements.md) и
[замечания к разговору](06-gim-stakeholder-answers.md).
**Числовые якоря, равные доли и арифметическое свёртывание — решение команды для
проверяемого пилота, не утверждение музея.**

## Как DeepSeek выставляет баллы

DeepSeek получает анкету и возвращает `scorecard` из пяти объектов в строгом
порядке. У каждого `criterion`, `level` (0–3 или null), `rationale` и
`evidence_question_ids`. Последнее — имена полей, для которых тот же JSON
содержит точные непустые цитаты `evidence`. Сервер проверяет схему, диапазон,
уникальность пяти критериев, источники и совпадение цитат с анкетой, затем
**сам** вычисляет общий балл. Присланное моделью числовое `score` отклоняется:
у модели оно обязано быть `null`.

| Группа | Что проверяем | Чего не делаем |
| --- | --- | --- |
| `motivation` — мотивация и осознанность | Конкретный интерес к истории, задачам музея, ожиданиям | Не штрафуем за краткость, пользу для резюме или отсутствие красивых формулировок |
| `skills` — опыт и навыки | Применимость заявленного опыта/навыков к выбранной роли, конкретные примеры | Не требуем прошлой работы в ГИМ, престижного вуза, диплома |
| `availability` — обучение и нагрузка | Названные часы/дни, регулярность, другие обязанности, реальные ограничения | Первый курс, полная ставка и совмещение — повод проверить риск, а не автоматический отказ; проверяем исключения |
| `form_and_contact` — анкета и связь | Содержательные ответы, возможность контакта, если указана | Закрытая страница VK/необязательное поле не ухудшают балл; аккаунт VK не сканируется |
| `logistics` — логистика | Подтверждённая возможность приезжать и выполнять интересующие задачи | Не угадываем адрес по вузу, не придумываем часы фондов или гарантированную удалённую работу |

**Одинаковые уровни для всех групп (пробные якоря):**

- **0** — в собственных ответах есть явное существенное противоречие выбранным задачам, не снятое другими указанными обстоятельствами. Не означает отказа.
- **1** — есть существенный подтверждённый риск или слабое соответствие.
- **2** — рабочее соответствие, но есть ограниченные неопределённости/вопросы.
- **3** — конкретное сильное соответствие с положительными примерами.
- **null** — данных недостаточно. Нельзя автоматически приравнивать к 0 или 1.

Незнание графика фондов, закрытая страница VK и отсутствие опыта не дают
основания автоматически поставить 0. Формальное условие возраста 18+ требует
дополнительного решения координатора и не заменяет содержательный разбор.

## Арифметика (сервер, не модель)

Пилотные группы **равноправны** лишь как временная, полностью прозрачная
базовая гипотеза. Итог `score_raw` = среднее известных `level`, округлённое
для отображения до двух знаков; `score` = округление точного среднего
до ближайшего целого с половиной вверх, диапазон 0–3. Пропуски не считаются
нулём. Итог возможен, только если оценены не менее 3 групп, включая мотивацию
и нагрузку. Иначе `score=null`, `score_status=insufficient_evidence` и
нужны дополнительные вопросы. При расчёте `score_status=pilot_unvalidated`,
`score_rubric=gim-five-groups-pilot-v1`, `rated_criteria_count` показывает
число оценённых групп.

**Пример арифметики:** уровни `2, 3, 1, 2, null` дают среднее 2,0,
итоговый балл 2; отсутствие логистики не считается нулём. Пять уровней
`3, 2, 1, 2, 2` также дают 2,0. Балл 2 не означает «берём» или «отказываем».

В режиме `rules_demo` оценка намеренно остаётся `null`; исторические
импортированные ответы до появления `scorecard` также остаются без балла.
Проверять реальную модель нужно только с синтетическими анкетами и флагом
`evaluation_mode=llm` (отключённый fallback). Новая версия требует
`scorecard`, поэтому старые JSON без неё не считаются новым live-результатом.

## Что будет значить статистическая проверка

Базовые корреляции Александра из PDF (`R=0.577`, `R²=0.333`,
`adjusted R²=0.252`, `n=112`) — исторический разведочный анализ,
а не точность этой рубрики. Никакую точность ей ещё не приписываем.
Перед калибровкой музей должен определить, что именно исторический балл
0 означает: «не пригласили» или качество анкеты. Далее:

1. По 15 синтетическим анкетам независимо сравнить пять критериев,
   фактические цитаты, 1–2 вопроса интервью и направление с ожиданиями Евы;
   зафиксировать причины расхождений. В её документе пока 9 карточек, не 15.
2. На независимых исторических обезличенных записях согласовать смысл
   экспертных 0/1/2/3 и двойную разметку спорных случаев без просмотра AI.
3. Зафиксировать пилот до проверки на неиспользованном holdout, исключить
   дубли между сезонами и утечку ответов в настройку промпта.
4. На holdout оценить MAE по баллам, confusion matrix, quadratic weighted kappa,
   ранговое согласие и экспертные причины крупных расхождений; сравнить с
   простым baseline и между двумя кураторами.
5. Только после этих измерений решать, подходят ли такие уровни, равные веса,
   правило пропусков и агрегирование. Дальнейшая коррекция требует новой версии
   рубрики и нового holdout, а не заднего изменения старых оценок.

**Пилотный балл = приоритет для ручного рассмотрения гипотез, а не ранжирование
людей по качеству, прогноз активности или автоматический отбор.**
