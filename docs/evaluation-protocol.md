# Протокол исторической проверки / Historical evaluation protocol

## 1. Что именно является gold label

Перед любым расчётом куратор подтверждает смысл исторической шкалы и допустимость
локальной обработки данных. В заголовках исторических XLSX шкала сформулирована как:

| Балл | Историческая формулировка | Рабочее чтение для benchmark |
|---:|---|---|
| 0 | не позвали на очное собеседование / not invited | не приглашён или сведений недостаточно для приглашения |
| 1 | слабая анкета / weak | слабое соответствие по исторической формулировке |
| 2 | средняя анкета / medium | среднее соответствие |
| 3 | хорошая анкета / good | хорошее соответствие |

Это **ordinal-метка исторического решения**, а не утверждённая шкала качества
современного оценщика. Она смешивает качество анкеты и решение «приглашать / не
приглашать»; поэтому результаты нельзя называть точностью отбора или доказательством
приёма. Пустой балл — `unknown`, не ноль. Метки `accepted` и `active` независимы и
не выводятся из `expert_score`. Пилотная шкала приложения
`gim-five-groups-pilot-v1` пока не является утверждённой шкалой ГИМ.

Человек-куратор остаётся финальным принимающим решение. Evaluator только ранжирует
кандидатов, выделяет неопределённости и flags/подсвечивает риски; он не принимает
решение о приглашении, отказе или зачислении.

## 2. Подготовка и разбиение

Импорт выполняется только локально:

```text
python -m scripts.import_historical \
  --source "materials/gim/Анкеты 2024 осень.xlsx" \
  --source "materials/gim/Анкеты 2025 весна.xlsx" --dry-run
```

HTTP, внешние базы и автоматические обращения к LLM запрещены. Исторические поля не
прогоняются через валидацию новой анкеты; отсутствующие мотивация, часы и контакты
явно остаются missing. Год рождения без дня и месяца, а также Excel-артефакт 1900,
не становятся полноценной датой.

До просмотра результатов фиксируются код, протокол, список входных файлов, их хеши,
`random_state=42` и критерии приемлемости. Разбиение `split_records` имеет два
назначения:

* **train/tune** — только данные до holdout (в текущем историческом наборе — 2024);
  здесь разрешено определить majority baseline и отладить правила;
* **2025 holdout** — все пригодные размеченные записи 2025, не используемые для
  выбора правил, порогов или текста отчёта.

Одинаковые семантические анкеты группируются по fingerprint и целиком попадают в
одну часть; иначе получится утечка дубликатов. `random_state=42` делает split
воспроизводимым. Если протокол запускается на данных с несколькими сезонами, год
2025 всё равно остаётся финальным holdout, а не случайной частью tune. Не следует
перебирать seed или порог после просмотра holdout.

## 3. Контракт evaluator и mock/live режимы

Публичный offline-контракт скрипта состоит из
`compute_metrics`, `split_records`, `evaluate_records`, `write_reports`,
`anonymize_record`, `build_application`. Predictions имеют вид
`candidate_id -> 0/1/2/3/null`; для holdout передаются ровно ID размеченных записей.
`null` означает abstention/недостаток сведений, а не плохого кандидата.

Mock-режим детерминированный, быстрый и не обращается к сети или платному API. Он
нужен для проверки пайплайна, формул, приватности и формата отчёта, но не является
оценкой качества модели. Live-режим требует отдельного явного запуска и настроенного
провайдера; его стоимость, задержка, версия модели и недетерминизм должны быть
зафиксированы отдельно. Отсутствие live-запуска не заменяется mock-результатом.

## 4. Метрики и baselines

Пусть `y_i` — исторический балл, `p_i` — числовой prediction, а `N_num` — число
пар с `p_i != null`. Матрица ошибок строится по четырём классам:

```text
M[i,j] = count(y_i = i and p_i = j),  i,j ∈ {0,1,2,3}
```

Это ровно матрица **4×4**, и `sum(M) == N_num`: null в неё не попадает.

Обязательные показатели:

* `coverage = N_num / N`; `null_count = N - N_num`;
* `MAE = Σ |y_i - p_i| / N_num` по числовым парам; это понятная средняя
  ordinal-ошибка и она учитывает, что 0→3 хуже, чем 2→3;
* `accuracy = count(y_i == p_i) / N`; null считается несовпадением, чтобы нельзя
  было повысить accuracy массовым abstention;
* для каждого класса — support, precision, recall и F1; отсутствующий класс имеет
  F1=0; `Macro-F1 = (F1_0 + F1_1 + F1_2 + F1_3) / 4`;
* weighted kappa и bootstrap 95% interval для MAE (1000 повторов, фиксированный
  seed) — вспомогательные показатели, не замена MAE и Macro-F1;
* `large_errors` / blunders: `count(|y_i-p_i| >= 2)`. Любая такая ошибка считается
  существенным риском и должна быть flag в проверке; порог не означает автоматический
  отказ и не выбирается после holdout.

Почему не только accuracy: историческая шкала порядковая, поэтому близкие ошибки
должны отличаться от ошибок на два-три уровня; MAE это показывает. Почему не только
MAE: модель может хорошо угадывать соседние классы и плохо работать на отдельном
классе, поэтому Macro-F1 одинаково учитывает все четыре класса и не маскирует редкий
класс общим большинством.

Базовые сравнения обязательны:

1. **majority baseline** — самый частый `expert_score`, определённый только на
   train/tune; при ничьей выбирается меньший класс;
2. **fixed-2 baseline** — всегда предсказывает `2`, независимо от распределения.

Модель сравнивается с обоими baseline на одном и том же 2025 holdout. Baseline не
выдаётся за модель и не заменяет независимую кураторскую проверку.

## 5. Приватность и файлы результата

До evaluator запись проходит через `anonymize_record`: имя, email, телефон,
`vk_url`, ссылки и другие контакты не должны попадать в mock output, anomaly list,
логи или публичные отчёты. В anomaly/flag списках разрешены безопасный hash
`candidate_id`, баллы, величина ошибки и короткое объяснение без имени и raw text. В отчётах разрешены
агрегаты, метрики, confusion matrix, параметры split и технические статусы; сырые
ответы, цитаты и PII запрещены.

По умолчанию импорт — dry-run со сводкой без строк кандидатов. Разрешённый локальный
экспорт исходных записей создаётся только в игнорируемом
`reports/historical-local`, с правами `0600`, без перезаписи; на Windows отдельно
проверяются ACL. Не копировать raw dataset в `qa/`, artifacts, PR, чат или публичный
репозиторий. Файлы отчёта должны создаваться в переданном локальном каталоге и не
содержать имён из synthetic или real records.

## 6. Проверки и ограничения интерпретации

`tests/test_evaluation_benchmark.py` использует только временные синтетические
записи и, при проверке импорта, tiny XLSX с замокнутым `read_sources`; платные API и
сеть не используются. Проверяются 4×4 matrix, MAE, coverage/null, per-class/F1,
majority и fixed-2 baseline, детерминированность split, anonymization, отсутствие
raw text/PII в mock output и отчётах, ID-only anomalies и наличие metrics/confusion.

Эти tests проверяют контракт и отсутствие очевидной утечки, но не доказывают
точность модели. Реальные predictions holdout, независимая разметка Евы и
подтверждение порога куратором должны быть получены отдельно. Не публиковать
качество по направлению, активности или приёму без соответствующего gold label и не
подменять evaluator историческими коэффициентами или baseline.
