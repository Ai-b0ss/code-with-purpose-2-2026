# Самостоятельный ИИ-оценщик ГИМ

`backend/evaluator.py` готов к вызову из Python. `backend/app.py` и
`frontend/index.html` не изменены: действующие HTTP-маршруты пока вызывают
`evaluate_demo()`. Подключение `evaluate()` к API — следующий согласованный шаг.

## Запуск

Используются существующие зависимости `requirements.txt`, дополнительных SDK нет.
Из корня репозитория:

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

```python
from backend.app import ApplicationInput
from backend.evaluator import evaluate, ChatCompletionsAdapter, EvaluationError

answers = ApplicationInput(
    applicant_name="Тестовый кандидат",
    age_over_18=True,
    motivation="Хочу помогать музею рассказывать об истории в видеоформате.",
    experience="Монтирую видео для студенческого проекта.",
    expectations="Практика монтажа и полезные исторические материалы.",
    availability_hours_month=24,
    other_commitments="Полная ставка, свободны субботы и вечера пятниц.",
    desired_direction="media",
)

# Работает без сети и модели.
demo = evaluate(answers, mode="demo")

# Адрес полного chat/completions endpoint вашего локального сервера.
# Название модели должно соответствовать загруженной на сервере модели.
adapter = ChatCompletionsAdapter(
    endpoint="http://localhost:8000/v1/chat/completions",
    model="your-loaded-model",
    timeout=30,
)
result = evaluate(answers, adapter=adapter)
```

HTTP-адаптер отправляет `model`, `messages`, `temperature: 0` и, по умолчанию,
`response_format: {"type": "json_object"}`. Ожидается ответ
`choices[0].message.content` со строкой JSON и `finish_reason: "stop"`.
Для сервера без JSON mode передайте `json_mode=False`: схема всё равно включена
в запрос и проверяется локально. Сервер обязан поддерживать указанный протокол;
адаптер не запускает сервер и не скачивает модель.

Альтернативно настройте окружение процесса (файл `.env` автоматически не читается):

```powershell
$env:GIM_EVALUATION_MODE = 'llm'  # без настройки используется demo
$env:GIM_LLM_ENDPOINT = 'http://localhost:8000/v1/chat/completions'
$env:GIM_LLM_MODEL = 'your-loaded-model'
$env:GIM_LLM_TIMEOUT = '30'      # секунды, >0 и <=300
$env:GIM_LLM_JSON_MODE = '1'     # 0 отключает response_format
# GIM_LLM_API_KEY — необязательный Bearer-токен, если сервер требует его
```

После этого `evaluate(answers)` использует окружение. Другие протоколы подключаются
реализацией `LLMAdapter.complete(system=..., user=..., schema=...) -> str`.
При внедрении в асинхронный API синхронный сетевой вызов следует выполнять в
thread pool либо в синхронном обработчике FastAPI.

## Контракт и ошибки

Все ключи результата `evaluate_demo()` сохранены. Дополнительно возвращается
`fit_for_museum`; `fit_for_candidate` отдельно описывает соответствие программы
ожиданиям человека. `score` всегда `null`, `score_status` — `not_calibrated`.
Режим указывается в `evaluation_mode`: `llm` либо `rules_demo`.
Подпись направления определяется локально по справочнику действующего API.
Успешный результат — обычный JSON-совместимый словарь.

Проверяются обязательные поля, типы, направления, отсутствие дополнительных
полей и дублирующихся JSON-ключей, непустые тексты и вопросы, ограничения длины,
отсутствие числового балла, а также цитаты `evidence`: они должны дословно
встречаться в указанном ответе. Числа и boolean цитируются в JSON-записи.
Markdown вместо JSON, усечённый ответ и отказ модели не считаются оценкой.

`EvaluationError.code`: `invalid_configuration`, `invalid_mode`,
`provider_unavailable` (включая HTTP-ошибки и таймаут),
`invalid_provider_response`, `incomplete_response`, `response_too_large`,
`invalid_model_json`. Сообщения не содержат ответов анкеты, ключей и тела ошибки
провайдера. Некорректный ввод анкеты вызывает стандартный Pydantic ValidationError.
Автоматических повторов сетевого запроса нет, время ожидания ограничено.

По умолчанию ошибки LLM поднимаются вызывающему коду. Только явный параметр
`fallback_to_demo=True` разрешает вернуть демо с `evaluation_error` и
`evaluation_mode: rules_demo`. Ошибки конфигурации не маскируются деморезультатом.

## Основания рекомендаций

- Пять групп Евы: `docs/Критерии_отбора_ГИМ.xlsx`, строки 5–9:
  мотивация; опыт/навыки; нагрузка; полнота/связь; логистика.
- Оригинал анкеты и критериев: `materials/gim/Анкета волонтера. Вопросы..docx`.
- Подтверждённые ответы: `docs/06-gim-stakeholder-answers.md` имеют приоритет
  над автоматическими штрафами таблицы. Первый курс, полная ставка и другие
  программы сами по себе не ведут к отказу. 16 ч/мес — сигнал, а не порог.
- График фондов: будни 10–18; наличие места и удалённых задач не гарантируется.
- Исторические анкеты 2024/2025 изучены как контекст схемы данных. В них есть
  шкала 0–3, пропуски, показатели приёма и активности. Они не отправляются модели,
  не включены в промпт как примеры и не используются как обученная шкала.
  Пропущенный балл не считается нулём. Веса не назначены.

Короткий текущий `ApplicationInput` не имеет отдельных полей города, курса,
канала связи и подробного графика. Имеющиеся сведения можно передать в
`other_commitments` и `followup_answer`. Модель должна отмечать пробелы,
а не считать отсутствие несуществующего в форме поля недостатком кандидата.

ФИО и ID исключены из запроса модели. Свободные ответы всё ещё могут содержать
личные сведения: используйте одобренный командой сервер. HTTP разрешён для
локального сервера; для удалённого сервера используйте HTTPS. Редиректы запрещены.

## Проверка и оставшаяся работа

Тесты без внешнего сервера проверяют два контрастных кандидата, контракт,
наличие правил в промпте, передачу времени и контекста, ошибки и явное демо.
HTTP round-trip использует локальный тестовый сервер с фиксированным ответом.
Это проверяет транспорт и валидацию, но не качество генерации настоящей модели.

Live-тест по умолчанию явно помечается `skipped`, а не успешным. Он запускается
только при `GIM_RUN_LIVE_TEST=1` вместе с `GIM_LLM_ENDPOINT` и `GIM_LLM_MODEL`.
В live-тесте fallback запрещён: недоступность сервера или неправильный JSON
приводят к провалу теста. До согласования бесплатного сервера этот флаг не включать.

Схема и дословные цитаты не гарантируют семантическую достоверность всего текста
и не исключают prompt injection. Правила «не придумывать» и оценки обеих сторон
заданы в системном промпте; перед приёмом нужна проверка куратором.
Остаются: запуск на выбранной живой модели, проверка рекомендаций Евой на
контрастных анкетах, калибровка на отложенных исторических данных, согласованное
подключение к HTTP API и общая интеграция с Google Sheets.

## Уточнение эксперта и проверка после интеграции

По словам музея первый курс, полная ставка и несколько других волонтёрских программ — отрицательные предварительные сигналы доступности. В объединённой ветке добавлен автономный модуль backend/availability_policy.py, который фиксирует их в possible_problems и fit_for_museum даже при пропуске со стороны LLM. Возможны индивидуальные исключения по подтверждённому графику. Нет автоматического отказа и выдуманных чисел 0–3.

Проверка: tests/test_availability_policy.py. **FastAPI ещё вызывает rules_demo** — переключение на реальную модель остаётся отдельной задачей.
