# Исправление контракта, уточнений и карточки куратора

Ветка исправления создаётся от main 648af50. Реальные отклонённые ответы на вымышленные анкеты воспроизводятся отдельными fixtures; прежние live-ошибки не списываются на недоступность провайдера.

## Контракт модели

- Источники evidence поддерживают точные верхнеуровневые поля и followup_answers.<id>. Другие вложенные пути не разрешены; неточные или выдуманные цитаты отвергаются.
- Новая модельная схема задаёт scorecard объектом с пятью обязательными ключами. Сохранённый формат остаётся списком для совместимости. Общий балл и подпись направления считает сервер; модель их не заполняет.
- При нарушении контракта разрешён ровно один запрос исправления по безопасным кодам. Ошибка провайдера не повторяется автоматически, demo не подставляется. Оба обращения укладываются в исходный транспортный timeout, если используется штатный HTTP-адаптер.
- Контакты, имя, ID и дата рождения исключены из обоих модельных запросов; передаются только признаки заполненного контакта. Свободные ответы могут содержать введённые самим кандидатом сведения; это не заменяет контроль доступа из #28.

## Отдельная проверка отсутствующего балла

Пять критериев обязательны. Итог вычисляется из уровней даже при отсутствии модельного поля score. Если известных уровней меньше трёх либо неизвестны мотивация/доступность, score=null и score_status=insufficient_evidence сопровождаются понятным score_explanation. Это допустимая нехватка сведений, а не ноль и не потерянный результат. Ошибочная схема получает ограниченный repair; после повторной ошибки финал не сохраняется.

## Отдельная проверка согласованности оценок

В промпте закреплены различия уровней навыков: конкретная релевантная задача и действия — сильное соответствие; общий опыт — рабочее. Самоописание помечается непроверенным, но одинаково для всех. Название вуза, длина текста и нагрузка не должны менять оценку навыков; нагрузка рассматривается отдельно. Это уточнение пилотных якорей, не статистическая калибровка и не обещание детерминированности модели. Живые повторные и парные сценарии проверяются отдельно от наличия балла.

## Вопросы кандидату и темы интервью

Один первоначальный раунд до двух вопросов; после ответов допускается ещё один новый вопрос при важном устранимом противоречии. Всего максимум три вопроса и два раунда. «Пока не знаю» завершает выпытывание того же факта. Изменение исходной анкеты сбрасывает прежние уточнения; черновик сохраняет тексты и ответы.

interview_focus — до двух тем для куратора на будущем очном интервью. Они не подменяют уточнения кандидату. Старое interview_questions сохранено для совместимости, новая генерация оставляет его пустым.

## Карточка и выгрузка

Локальная карточка показывает русский вердикт, объяснение, балл/причину отсутствия, пять критериев таблицей, конкретные риски, направление с обоснованием, темы интервью и исходные уточнения. Анкета и evidence свёрнуты.

CSV/Sheets имеют 43 колонки. Первые 32 позиции сохранены; добавлены вердикт, комментарий, пять уровней, пары вопросов/ответов, полная scorecard, статус и объяснение балла. Google range вычисляется по количеству колонок. Совместимый старый заголовок расширяется, противоречащий заголовок не перезаписывается. SQLite остаётся источником, восстановление доставки сохраняется.

## VK

VK-бот перенесён выборочно из feature/issue-4-full-form@bc55c88 без старого backend. Зависимости устанавливаются через requirements-vk.txt. BACKEND_URL указывает на работающий LLM backend, VK_GROUP_ID — на тестовое сообщество, VK_GROUP_TOKEN передаётся только через среду процесса/локальный секретный ввод.

Бот собирает также ожидания, хобби и другие программы; сохраняет исходные вопросы и все ответы. Ошибка предварительного анализа не пропускает уточнения. Повтор финала сохраняет ID и исходный профиль. Нулевая доступность допустима. Подключение Bots Long Poll не подтверждает сквозное прохождение анкеты: нужны настоящее сообщение кандидата, результат llm в SQLite и проверка кураторской карточки.

Реальный VK-тест в сообществе 242486526: PASS. Пользователь прошёл диалог, официальный Bots Long Poll передал анкету в backend, оба вопроса и ответа сохранены. Итог llm: 1/3, not_recommended_for_interview; уровни [0,null,1,2,null]. Прямой ответ об отсутствии интереса к неоплачиваемым задачам учтён в мотивации. Второй анализ не потребовал третьего вопроса. Повтор ID вернул created=false, прежнюю оценку и одну запись SQLite. Карточка куратора проверена; персональные поля не публикуются. Браузерная блокировка VK не обходилась.
