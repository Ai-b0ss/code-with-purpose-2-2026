# Граница данных

Кандидат отправляет анкету и получает только номер и безопасное подтверждение. Список, карточки, preview, CSV, рейтинг, аналитика, sync и удаление требуют `Authorization: Bearer …`. Создайте случайный ключ: `python -c "import secrets; print(secrets.token_urlsafe(32))"`, задайте `GIM_COORDINATOR_TOKEN` в локальном окружении сервера. При отсутствии ключа или длине менее 32 символов доступ закрыт. В `/admin` ключ вводится вручную и хранится только в памяти вкладки. Кнопка выхода очищает экран. Для удалённого использования требуется HTTPS; локально привязывайте сервер к 127.0.0.1. Ключ не включается в HTML, URL, ZIP, storage браузера или репозиторий. Общий ключ означает одну роль координатора, без персонального аудита сотрудников.

Ответы API запрещено кэшировать. Ошибки валидации не возвращают исходные значения. Исходные анкеты не обслуживаются через static. Локальные HTML-отчёты с ПД храните только в закрытом каталоге оператора с правами пользователя ОС; не переносите их в frontend.

По умолчанию внешний анализ API блокируется. `GIM_ALLOW_EXTERNAL_LLM=1` разрешает его только после того, как оператор установит основание обработки, разрешённого провайдера, сроки хранения, доступ сотрудников и текст согласия. Официальная политика https://shm.ru/politika-konfidentsialnosti/ является источником, но сама по себе не разрешает нашей системе передачу анкет стороннему провайдеру. Технический прототип не утверждает, что такое разрешение получено.

В LLM передаются только перечисленные смысловые поля, контакты представлены признаками наличия. Точные имя/контакты/дата и распространённые email, URL, телефоны внутри текста маскируются. Произвольный свободный текст нельзя гарантированно обезличить регулярными выражениями. Используйте синтетические данные до разрешения оператора. Исходные ответы сохраняются в SQLite дословно; замаскированное evidence относится к тексту, который видела модель.

Черновик web хранится в sessionStorage вкладки и удаляется после успеха/сброса. Старый localStorage v1 нужно очистить при миграции. Экспорты, скриншоты и отчёты являются отдельными копиями ПД. Не создавайте их без учёта срока/места хранения. Конкретный срок хранения и ответственное лицо устанавливаются оператором перед приёмом реальных анкет; автоматическое бессрочное хранение не является принятой политикой.

`DELETE /api/v1/admin/applications/{id}` отзывает резервирование, запрещает повторную регистрацию этого ID, очищает соответствующие строки Google (если настроен) и удаляет SQLite запись. Идущая оценка не может восстановить удалённую анкету. Если sync выполняется, удаление возвращает 409 до его завершения. Если Google недоступен, 503 оставляет запись в delete_failed, повтор удаляет её после восстановления Google. При зависшем deleting после аварии оператор проверяет отсутствие процесса удаления и переводит состояние в delete_failed локально. Не восстанавливайте резервную копию без повторного применения списка отозванных ID.

Отдельные CSV/HTML/ZIP, резервные копии, история VK и старые браузерные черновики не удаляются этим маршрутом. Оператор ведёт журнал копий и вручную удаляет их при отзыве/истечении срока. Хеши отозванных ID хранятся без анкеты для защиты от восстановления. До проверки всей цепочки удаления и утверждения политики реальных ПД публичный сбор запрещён.
