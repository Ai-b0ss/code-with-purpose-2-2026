## Google Sheets: автоматическая запись

После сохранения анкеты в SQLite сервер сразу пишет её в Google Sheets. Одна заявка занимает одну строку вкладки `Заявки API`: перед записью сервер ищет ID в колонке A и при повторе обновляет найденную строку. После записи Google API автоматически подбирает ширину всех 32 колонок. CSV-экспорт оставлен как резервная выгрузка.

**Живая проверка 22.10.2026:** вымышленные ID записаны через Google Sheets API в [тестовую таблицу](https://docs.google.com/spreadsheets/d/1iQEevsZFMB307trbntFZWQkatYBOVUiMNBqGzZoDXzE/edit). [Строка A2](https://docs.google.com/spreadsheets/d/1iQEevsZFMB307trbntFZWQkatYBOVUiMNBqGzZoDXzE/edit#gid=220874114&range=A2), ID `synthetic-google-5687c84c7576`: повтор вернул `created=false`, обновление через Sheets API оставило тот же адрес и одну строку. [Строка A3](https://docs.google.com/spreadsheets/d/1iQEevsZFMB307trbntFZWQkatYBOVUiMNBqGzZoDXzE/edit#gid=220874114&range=A3), ID `synthetic-google-d0c1707bbc57`: сначала Google вернул `404`, при этом SQLite сохранила одну запись, затем повтор синхронизировал её. [Строка A4](https://docs.google.com/spreadsheets/d/1iQEevsZFMB307trbntFZWQkatYBOVUiMNBqGzZoDXzE/edit#gid=220874114&range=A4), ID `synthetic-parallel-666cc555c0e9`: два параллельных вызова дали одну строку. Контрольное чтение Google API показало ровно одну строку для каждого ID и метаданные ширины всех 32 колонок.

[Полный HTTP-прогон с реальным Google Sheets API](20-google-sheets-cloud-http-qa-20261022.md): три дополнительные синтетические заявки, повтор ID, параллельная отправка, сбой Google и восстановление после перезапуска сервера.

Настройка (ключ в репозиторий и чат не отправлять):

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект, включите **Google Sheets API**, создайте **Service Account** и JSON-ключ для него.
2. В нужной Google-таблице нажмите «Настроить доступ» и дайте адресу `client_email` из JSON-ключа права **Редактор**. Для проверки лучше создать отдельную таблицу без реальных персональных данных.
3. Перед запуском сервера задайте переменные окружения:

```powershell
$env:GIM_GOOGLE_SPREADSHEET_ID = "ID_между_/d/_и_/edit_в_ссылке"
$env:GIM_GOOGLE_CREDENTIALS_FILE = "C:\путь\вне\репозитория\service-account.json"
$env:GIM_GOOGLE_SHEET_NAME = "Заявки API"  # необязательно
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8765
```

Для постоянного локального запуска можно записать эти три значения в `.env` в корне проекта (файл игнорируется Git). `run.bat`, `run.sh` и `scripts/launchers/start-reformboss.ps1` передают его Uvicorn через `--env-file`. После изменения `.env` перезапустите сервер. Тесты не загружают `.env`, поэтому их синтетические заявки не попадут в Google.

Без переменных анкета всё равно сохраняется в SQLite, а `sheet_sync.status` будет `failed` с `error=google_not_configured`. При ошибке Google статус также `failed`, а локальная запись остаётся. После исправления доступа повторите синхронизацию: `POST /api/v1/applications/{application_id}/sync`. Статус, код ошибки и ссылка на строку видны в ответах `POST` и `GET /api/v1/applications/{application_id}`; `synced` означает успешную запись и подбор ширины. Повтор того же ID не запускает оценщик и не добавляет строку. Если Google успел записать строку, но ответ потерялся, повтор найдёт её по ID и обновит.

Быстрая живая проверка без чужих ПД: `python -m scripts.check_google_sheets_live`. Скрипт создаёт одну вымышленную заявку во временной SQLite, повторяет её ID и печатает ссылку на строку. Для проверки ошибки временно уберите доступ у service account, отправьте другую синтетическую анкету, проверьте `failed` и запись в SQLite, верните доступ и вызовите endpoint `/sync`.

Веб-анкета для кандидатов в волонтёры ГИМ: вопросы и уточнения → подтверждение кандидату → сохранение ответов и внутренней рекомендации → выгрузка для координатора. Целевое время заполнения — **5–7 минут**, реальный замер командой ещё нужен.

**Исправление конкурирующих повторов ID ([PR #39](https://github.com/Ai-b0ss/code-with-purpose-2-2026/pull/39), уже в `main`):** SQLite резервирует ID до запуска медленного оценщика. Одновременные запросы с одним ID используют один сохранённый результат, разные ID не ждут друг друга из-за открытой транзакции. Пропавшая модель освобождает резерв; брошенная при остановке сервера запись может быть перехвачена после 10 минут. Второй запрос при слишком долгом ожидании получает 409 с Retry-After, а не серверную ошибку 500. Это гарантия одной строки SQLite, не гарантия exactly-once платного вызова через рестарт процесса. [Детали и тесты](19-sqlite-reservation-20261021.md).

**Исправление вопросов [PR #38](https://github.com/Ai-b0ss/code-with-purpose-2-2026/pull/38):** не более 2 приоритетных вопросов для собеседования и 3 уточнений в форме. Непроверенное расписание фондов и норматив 8–12 часов удалены из формулировок. **Регрессия после [PR #39](https://github.com/Ai-b0ss/code-with-purpose-2-2026/pull/39):** 54 pytest PASS / 1 live SKIP и 73 локальные smoke-проверки PASS / 1 SKIP. ## Запуск ReformBoss (настоящая LLM)

Добавлен [`scripts/launchers/start-reformboss.ps1`](../scripts/launchers/start-reformboss.ps1): по умолчанию проверяет `deepseek-v4.1-flash` через `https://api.reformboss.com/v1/chat/completions` на вымышленном кандидате, затем поднимает приложение в режиме `llm`. Ключ запрашивается **видимым вводом** (не показывайте экран во время ввода) и не записывается на диск.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\launchers\start-reformboss.ps1
```

`-TimeoutSeconds 180` — таймаут запроса к провайдеру (по умолчанию 180, диапазон 1–300 с); `-SkipProbe` — запустить без повторного LLM-пробника; `-Port 8766` — выбрать желаемый начальный порт (по умолчанию 8765 с автопереходом на следующий свободный); `-Model glm-5.3` — переключить модель; `-Compare` — три реальные API-вызова для DeepSeek, GLM и Kimi; `-DisableJsonMode` — обход несовместимого `response_format`. Живой запрос к `deepseek-v4.1-flash` **успешен (37,8 с; валидный JSON, 12 evidence, score=null и риск первого курса отражён)**. Старый порт `8765` оказался занят; [PR #26](https://github.com/Ai-b0ss/code-with-purpose-2-2026/pull/26) добавил автоматический поиск свободного порта. Чтобы не повторять долгий вызов при запуске, используйте `-SkipProbe`. [Инструкция](11-llm-evaluator.md).

## Запуск на своём ноутбуке

Нужны Git и Python 3.11+.

```powershell
git clone https://github.com/Ai-b0ss/code-with-purpose-2-2026.git
cd code-with-purpose-2-2026
python -m pip install -r requirements.txt
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8765
```

На Windows можно запустить `run.bat`. Откройте **http://127.0.0.1:8765** *на том же компьютере*. Установка и запуск тестов одной командой в Windows — `scripts/launchers/run-tests.bat`. Эти тесты не требуют GitHub Actions или платных ключей.

**По умолчанию `rules_demo`.** Чтобы попробовать настоящую совместимую LLM, нужно отдельно настроить `GIM_EVALUATION_MODE=llm`, `GIM_LLM_ENDPOINT` (полный URL `/v1/chat/completions`) и `GIM_LLM_MODEL`; ключ `GIM_LLM_API_KEY` необязателен для локальной модели. Ненастроенную модель не считать активной. [Подробная настройка](11-llm-evaluator.md).
