## Воспроизведённые дефекты и риски интеграции

### 1. Параллельная идемпотентность: P0, #31

Временная SQLite, два ThreadPoolExecutor-запроса с одинаковым application_id; подставной evaluator синхронизирован Barrier(2), внешних запросов нет.

| Исходник | Вызовов оценщика | Строк | Ответы |
| --- | --- | --- | --- |
| main 1e5b626 | 2 | 1 | Один created=true, второй IntegrityError |
| Илья 4ccefa8 | 2 | 1 | created=true / created=false |

INSERT OR IGNORE полезен, но переносить его после двух оплаченных LLM-вызовов недостаточно. Нужна атомарная резервация ID перед обработкой. Проверенный последовательный повтор main остаётся рабочим; обнаружен дополнительный сценарий, который прежняя приёмка не покрывала.

### 2. Новые сессии отсутствуют в CSV: P0 перед миграцией, #32

TestClient, изолированные sessions/PII/legacy SQLite, подставной assess: заполнена сессия, submit вернул 202, result=SCORED. Затем GET export.csv содержит только заголовок: **0 строк**, session_id отсутствует. Frontend использует sessions, экспорт — applications. Новому хранилищу нужен общий exporter/Sheets-source.

### 3. Отзыв согласия оставляет снимок ответов: P1, #32/#28

После той же тестовой сессии consent=false возвращает CLOSED. Количество run_inputs до/после **1 → 1**, синтетическая мотивация остаётся в answers snapshot. Код удаляет answers/contacts/session_runs, но не run_inputs; текущий тест проверяет только первые два хранилища. Нужно также учесть одновременно работающую фоновую оценку.

### 4. Ошибочная разметка inclusive: P1, #32

`backend/historical.py:59`: значение `("инклюз")` — строка. `any(word in role_text for word in words)` проверяет отдельные буквы. При воспроизведении корпуса **72 из 113 уникальных анкет** получили inclusive при отсутствии подстроки «инклюз» в исходном поле направления. Нужен tuple `("инклюз",)` и перестроение role_ids/графа; изменения PDF недостаточно.

### 5. Контракт модели и ожидание снова расходятся: #32

- scoring.py:120 задаёт OpenAI chat endpoint независимо от GIM_LLM_ENDPOINT; нужен OPENAI_API_KEY. Ключ ReformBoss не является ключом OpenAI.
- Embeddings/retrieval требуют OpenAI API, вектора 1536. Подменять модель чата без решения по embeddings недостаточно.
- start-scoring не задаёт timeout; generic adapter без env ждёт 30 с. Frontend опрашивает результат до 60 раз по секунде; оценка/повтор может занимать дольше. У нас измерено 93 с для одного полного DeepSeek-запроса.
- BackgroundTasks живёт в процессе FastAPI; после остановки работа не восстанавливается автоматически. Нужны recovery и согласованный deadline.

### 6. Граница доступа и персональные данные: #28

Main исключает из LLM только applicant_name/application_id; email, vk_url, birth_date пока остаются. В scoring.py Саши есть полезный ANSWER_FIELDS allowlist, но старый llm-путь его не использует. Session-result выдаёт подробный evaluation без auth; функция coordinator_auth ни к одному маршруту не подключена. HTML-показ аналитики в пилоте также расходится с текущим публичным экраном.

### 7. Новая рубрика и источники не равны утверждённой политике

PDF 03_arch прямо называет веса проектными/некалиброванными. Его предложение включает другой балл и допускает Telegram, тогда как исходное ТЗ исключает Telegram.
