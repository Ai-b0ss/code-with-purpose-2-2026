# ГИМ — план реализации до защиты

**21–22 октября 2026.** Этот план описывает последовательность работ и критерии готовности, а не уже пройденные этапы. [Текущий статус — в README](../README.md).

## Контрольные этапы

| Этап | Что делаем | Готово, когда |
| --- | --- | --- |
| **0. Техническая основа — выполнено** | Frontend, FastAPI, SQLite, сохранение, CSV, тесты | Сервер запускается, тестовая анкета сохраняется, CSV скачивается; PR #11 слит |
| **1. Полная анкета** | Илья переносит обязательные музейные вопросы и улучшает шаги/уточнения | Ева проходит анкету за 5–7 минут, данные доходят до API |
| **2. Настоящие рекомендации** | Игорь подключает LLM, обоснования, вопросы собеседования и рубрику | Два разных кандидата получают осмысленные, различающиеся, валидируемые ответы; demo-rule режим остаётся резервом |
| **3. Таблица музея** | Саня связывает заявку с Google Sheets, унифицирует колонки, проверяет повторную запись | Одна анкета появляется в нужной Google-таблице, повторная отправка не создаёт дубль; Excel/CSV — резерв |
| **4. Калибровка и QA** | Команда проверяет исторические оценки и контрастные случаи | Есть понятные причины расхождений с куратором, записанные дефекты и замер UX |
| **5. Финальный прогон** | Полный сценарий, репетиция, резервная демонстрация | На ноутбуке защиты работают заполнение, рекомендации и таблица, репетиция уложилась в регламент |

## Ближайший рабочий спринт (60–90 минут от начала)

1. **0–10 минут:** каждый запускает `main`; Илья и Игорь согласуют поля, Саня берёт экспорт, Ева — список тестов. Не использовать экспериментальный контракт неслитого PR.
2. **10–45 минут:** Илья дополняет форму, Игорь — отдельный LLM-оценщик, Саня — адаптер Google Sheets, Ева сверяет с требованиями и оценивает три анкеты.
3. **45–65 минут:** первый общий запуск с новым оценщиком и записью результата; при проблеме с Sheets временно выгрузить CSV и открыть в таблице.
4. **65–90 минут:** тест повторной отправки, недостающих ответов и ошибок модели; запись блокеров в соответствующую Issue.

**Правило:** сначала работающий end-to-end, затем улучшения. Отдельные «идеальные» модули, которые не стыкуются, не считаются готовым результатом.

## Распределение и зависимости

- **Илья → [#4](../issues/4):** `frontend/index.html`, интерфейс и UX.
- **Игорь → [#5](../issues/5):** оценщик, рубрика и версионирование промптов.
- **Саня → [#6](../issues/6):** SQLite/экспорт, Google Sheets. Фактическую доступность разработчика уточняет команда.
- **Ева → [#8](../issues/8):** тестовые кандидаты, рубрика, замер 5–7 минут, QA.
- **Интеграция → [#9](../issues/9):** Игорь координирует, остальные проверяют свой слой.

Перед защитой: **заморозить функции**, проверить приложение на нужном ноутбуке и иметь резервный CSV/локальный демо-режим. Точное время технической сдачи уточнить у организаторов; ранее сообщалось о начале презентаций 22 октября около 13:30.

**P0:** работает анкета, настоящие рекомендации, итоговая Google-таблица, три пользовательских сценария. **P1:** комфортный дизайн, улучшения сравнения с историей. **Не начинать до P0:** VK, отдельный сложный дашборд, CRM, ML с нуля.
