# ГИМ — план реализации до защиты

**21–22 октября 2026.** Этот план описывает последовательность работ и критерии готовности, а не уже пройденные этапы. [Текущий статус — в README](../README.md).

## Контрольные этапы

| Этап | Что делаем | Готово, когда |
| --- | --- | --- |
| **0. Техническая основа — выполнено** | Frontend, FastAPI, SQLite, сохранение, CSV, тесты | Сервер запускается, тестовая анкета сохраняется, CSV скачивается; PR #11 слит |
| **1. Полная анкета** | Илья переносит обязательные музейные вопросы и улучшает шаги/уточнения | Ева проходит анкету за 5–7 минут, данные доходят до API |
| **2. Настоящие рекомендации** | PR #13 предлагает отдельный модуль и тесты; ещё нужно согласовать его подключение к FastAPI и live-вызов | Два разных кандидата получают обоснованные ответы **на реальном LLM**, при отказе модели остаётся явно помеченный demo-резерв |
| **3. Таблица музея** | Саня связывает заявку с Google Sheets, унифицирует колонки, проверяет повторную запись | Одна анкета появляется в нужной Google-таблице, повторная отправка не создаёт дубль; Excel/CSV — резерв |
| **4. Калибровка и QA** | Команда проверяет исторические оценки и контрастные случаи | Есть понятные причины расхождений с куратором, записанные дефекты и замер UX |
| **5. Финальный прогон** | Полный сценарий, репетиция, резервная демонстрация | На ноутбуке защиты работают заполнение, рекомендации и таблица, репетиция уложилась в регламент |

## Следующий интеграционный этап (после первых PR)

1. **Игорь / AI:** просмотреть [PR #13](https://github.com/Ai-b0ss/code-with-purpose-2-2026/pull/13). Есть независимый оценщик и offline-контракт, но в `main` API всё ещё вызывает `evaluate_demo()`. Прежде чем подключать, выбрать доступный LLM endpoint и провести реальный тест.
2. **Тесты:** проверить [PR #14](https://github.com/Ai-b0ss/code-with-purpose-2-2026/pull/14) только после синхронизации с финальной версией #13. Его ветка включает старые копии `backend/evaluator.py`, `tests/test_evaluator.py` и `docs/11-llm-evaluator.md`; сначала согласовать изменения, не перезаписывать #13.
3. **Илья / UI:** довести полный состав вопросов анкеты; не ждать готовности живого LLM, использовать текущий API/mock.
4. **Ева / QA:** отдать минимум 4 контрастных сценария и ожидаемые рекомендации; проверка логики не ждёт завершения дизайна.
5. **Александр / backend:** `r0shn1ch` получил доступ к приватному GitHub с правами **Write**. Пока Issue не назначена; после принятия приглашения согласовать задачи по Google Sheets и файл интеграции.
6. **Сборка:** после проверки PR и согласования точек интеграции обновить `main`, повторить локальные тесты и пройти анкету от UI до Google Sheets.

**Правило:** сначала работающий end-to-end, затем улучшения. Отдельные «идеальные» модули, которые не стыкуются, не считаются готовым результатом.
