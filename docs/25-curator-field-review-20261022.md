# Проверка исторических смысловых меток

`data/historical_field_review_queue_v7.jsonl` содержит предварительные
метки моделей для 113 уникальных анкет. После ужесточения проверки цитат
три поля локальная модель не смогла подтвердить; облачный повтор подтвердил
их без изменения слов в цитатах. Одна из категорий при этом изменилась по
сравнению с предыдущим проходом, поэтому все метки требуют проверки
куратором. Текстов анкет в очереди нет.
Очередь создана по прежней таксономии `gim-field-quality-v1`: в ней
ответ «опыта нет» мог получить обычный уровень качества. Текущая
таксономия `v2` выделяет нейтральную категорию `explicit_none`.
Старый файл оставлен как подсказка для ручной проверки, но уже не
допускается к пересчёту рабочих медиан без повторной разметки.
В актуальных XLSX есть общий исторический балл анкеты, но нет числового
качества каждого поля. Новая очередь `v2` создаётся отдельно командой
`python -m scripts.classify_historical_fields --out data/historical_field_review_queue_v9.jsonl --limit 113 --resume --salvage-errors`.
Каждая её строка хранит имя последней ответившей модели, список
попыток и безопасные коды сбоев без текста ответов. Незавершённый
первый проход `v8` оставлен только для технического аудита и не годится
для калибровки.
Её метки тоже остаются предварительным мнением модели; заполненность
очереди не означает одобрения куратором. Рабочую калибровку теперь нельзя
перезаписать никакой предварительной модельной очередью.

`python -m scripts.compare_field_queues` сравнивает старую и новую очереди
по хэшам, не читая исходные ответы. Агрегат показывает число расхождений
по каждому полю, а JSONL без текстов можно подать в
`scripts.curate_historical_labels --queue data/historical_field_review_queue_v9.jsonl --priority-audit data/historical_queue_v7_v9_disagreements.jsonl`.
Отчёт по неполному проходу содержит `complete_coverage=false` и не
должен трактоваться как итоговая доля несогласия.

На компьютере с исходными XLSX запустите:

```powershell
python -m scripts.curate_historical_labels
```

## Независимый аудит спорных полей

`python -m scripts.audit_historical_field_labels` повторно классифицирует
предварительные категории `unclear`, `off_topic`, `nonsense`, `abusive` и
`instruction_attempt` без показа модели прежней метки, исторического балла
или итога приёма. Отчёт в `data/historical_field_label_audit.jsonl` содержит
только хэш анкеты, поле, пару категорий и имя ответившей модели; ответов,
цитат и контактов в нём нет. При недоступности облачных моделей используется
настроенная локальная модель. Отчёт остаётся модельным мнением, а не
кураторской разметкой.

На текущих источниках 19 полей попали в аудит, `deepseek-v4.1-flash`
согласилась с предварительной категорией в 7 и разошлась в 12, ошибок
провайдера не было. Оба прежних `nonsense` вошли в расхождения. Поэтому
12 спорных меток были исключены из прежних пилотных медиан, но исходная
очередь не переписана. Файл `knowledge/field_calibration.json` сохранён
для аудита с `taxonomy_version=gim-field-quality-v1`; текущий сервер
возвращает `field_median_status=stale_taxonomy` и вклад медианы 0.
Пересчитывать его из старой очереди как версию `v2` нельзя.

Чтобы сначала разобрать расхождения вручную, используйте:

```powershell
python -m scripts.curate_historical_labels --priority-audit data/historical_field_label_audit.jsonl
```

Дополнительно проведена фиксированная проверка 20 положительных меток:
по одному ответу каждой пары «сезон × поле × категория» (`specific_relevant`
или `relevant_general`), выбор по хэшу без учёта исторического балла. Команда:

```powershell
python -m scripts.audit_historical_field_labels --mode positive
```

Получилось 13 совпадений и 7 расхождений, распределённых между обоими
сезонами. Запуск начинался с `glm-5.3`, но только 3 результата получены от
неё; оставшиеся 17 пришли от резервной `deepseek-v4.1-flash`. Поэтому это
не измерение согласия двух фиксированных моделей. Положительные метки
не исключались автоматически из рабочих медиан: небольшой диагностический
срез не даёт основания выбирать «правильный» уровень качества.
Его расхождения можно также поднять наверх очереди куратора:

```powershell
python -m scripts.curate_historical_labels --priority-audit data/historical_field_label_audit.jsonl --priority-audit data/historical_positive_label_audit.jsonl
```

Команда сопоставляет запись по хэшу с исходной таблицей и показывает
ответ только в локальном терминале. Исторический балл и итог приема
скрыты во время разметки, чтобы не подгонять оценку отдельного поля
под известный исход. `Enter` подтверждает предложенную категорию,
номер или название выбирает другую; затем можно подтвердить или
исправить числовое качество 0–3. `s` пропускает строку, `q` завершает работу.
Для очереди старой версии `Enter` больше не подтверждает предложенную
категорию: куратор должен выбрать категорию текущей таксономии явно.
Незавершенная строка не сохраняется. Повторный запуск пропускает уже
утвержденные хэши.

Утвержденные метки пишутся в игнорируемый Git файл
`data/curator_reviewed_fields.jsonl`. В нем есть только хэш строки,
версия таксономии, название набора, категории и числовые уровни; нет текста ответа,
ФИО, контактов или исторического исхода. Терминал при просмотре
показывает исходные ответы, поэтому используйте закрытый рабочий экран
и не публикуйте запись сеанса.

После утверждения **всех 113 строк** можно пересчитать рабочие медианы:

```powershell
python -m scripts.build_field_calibration data/curator_reviewed_fields.jsonl
```

Команда откажется заменять рабочий файл, пока набор утвержденных хэшей
не совпадает с текущими историческими таблицами. Для проверки частичной
разметки без установки в рабочую оценку используйте
`--out data/field_calibration_curator_preview.json`. После изменения
исходных XLSX сначала проверьте `python -m scripts.verify_knowledge_sources`,
обновите разметку и только затем пересчитывайте медианы. Прежняя
пилотная калибровка из меток модели остается помеченной
`llm_historical_fields` до полной проверки.
