# Запуск и восстановление

Python 3.11+. Создайте venv и установите requirements.txt; для тестов requirements-dev.txt, для VK requirements-vk.txt. Модель и Google по умолчанию не вызываются.

Локальная демонстрация: задайте `GIM_EVALUATION_MODE=demo`, `GIM_DB_PATH` на отдельную базу и `GIM_COORDINATOR_TOKEN` (случайный ключ минимум 32 символа), затем `python -m uvicorn backend.app:app --host 127.0.0.1 --port 8765`. Анкета — `/`, кабинет — `/admin`. Ключ вводится в кабинете вручную. Windows `START-TEAM.cmd -Demo` (или `powershell -NoProfile -ExecutionPolicy Bypass -File .\team-start.ps1 -Demo`) настраивает venv и запускает локальный demo без ключа модели; start-reformboss.ps1 предназначен для синтетической live-демонстрации и явно разрешает внешний анализ. Другие способы запуска llm требуют GIM_ALLOW_EXTERNAL_LLM=1 после проверки оснований обработки. Без этой настройки API возвращает 503 до вызова модели.

Проверка готовности: GET /api/v1/health сообщает режим; это liveness, не гарантия готовности провайдера/Google. Реальную готовность проверяйте одной разрешённой вымышленной заявкой, затем защищённой карточкой. Отсутствие Google отражается как failed sync, SQLite остаётся источником истины. Наличие HTTP 200 на главной не доказывает сохранение заявки.

Остановка Ctrl+C, затем запуск той же командой с тем же GIM_DB_PATH. Не меняйте номер заявки при повторе после потери ответа. То же содержимое и ID возвращают registered/created=false; конфликтующее содержимое получает 409. Резерв до модели — короткая транзакция; TTL 10 минут. После аварии неизвестный результат внешнего вызова может потребовать нового вызова после TTL, exactly-once биллинг не гарантируется. Истёкший worker не может записать результат под чужим токеном.

Состояния: черновик → уточнения → резерв ID → LLM → SQLite commit → Google delivery → публичное подтверждение. Ошибка до SQLite сохраняет черновик в web sessionStorage/VK; 429/timeout/provider error возвращает 503, молчаливый demo fallback выключен. Refresh web сохраняет черновик в той же вкладке, закрытие вкладки может удалить его. Черновики VK сохраняются только после согласия, TTL 24 часа, очищаются при /reset и DONE. GIM_VK_SESSION_DB задаёт путь, по умолчанию data/vk-sessions.sqlite3. История переписки на стороне VK существует отдельно. SQLite drafts не является шифрованием: нужны права пользователя ОС и защищённый диск.

Google сбой не удаляет заявку. После восстановления координатор вызывает `POST /api/v1/applications/{id}/sync` с Bearer ключом. Поиск строки по ID делает повтор после потерянного ответа безопасным; при внешних ручных дубликатах возвращается ошибка, требуется ручная сверка. Не запускайте массовые неконтролируемые retry. Аварийный локальный экспорт: авторизованный GET /api/v1/export.csv или одиночный /api/v1/admin/applications/{id}/export.csv. Одна CSV-запись может занимать несколько физических строк из-за переносов внутри ответа.

Резервирование: SQLite backup через sqlite3.Connection.backup в каталог с правами оператора; отдельно учитывайте VK draft DB и журнал отозванных ID. Для restore остановите собственные сервер/бот, сохраните старые файлы, восстановите копию и примените все отзывы/удаления после даты копии до запуска. Проверьте количество ID и контрольную вымышленную заявку. Не восстанавливайте отозванные анкеты. Резервные копии/CSV/HTML/скриншоты подчиняются срокам оператора и удаляются отдельно (docs/privacy-and-security.md).

Ежедневно: сверить новые заявки, очередь insufficient_evidence, ошибки sync, состояние удалений, срок копий и свободное место. Не превращать предварительный вердикт в окончательное решение. Метрики/отчёты не должны раскрывать ПД вне кабинета.

Проверки: `python -m pytest -q`, `python tests/run_local_smoke.py`, `python -m scripts.make_team_portable`, `git diff --check`. ZIP содержит allowlist и SHA256 manifest, исключает материалы и данные. Чистый Windows ноутбук, реальные Google/VK и пользовательские 5–7 минут должны проверяться отдельно на закреплённом release SHA. Linux smoke и mocked provider не подтверждают их автоматически.

Проверенный новый пакет: releases/GIM_PRODUCT_LOCAL_DEMO_20261022.zip. В нём только allowlist исходников и документация, без материалов/исторических анкет/ключей/SQLite. Протокол фактического Windows и Excel прогона: qa/windows-excel-acceptance-20261022.md. CSV проверен обычным открытием Excel 16.0; legacy OpenText для многострочных ответов не поддерживается.

Дополнительная проверка сбоев: `python tests/real_http_recovery.py`. Поднимает собственные backend и контролируемый HTTP-провайдер, использует временную SQLite, проверяет безопасные ошибки, повторы и восстановление после kill. Внешние API не вызываются; это не проверка качества ИИ. Протокол и ограничения: qa/autonomous-checks-20261022.md.

Для синтетической live-серии после отдельной настройки backend и ключа координатора: `python -m scripts.qa_agent_live --base http://127.0.0.1:8765 --only repeat1 --workers 1`; затем полный набор без --only. Сначала убедитесь в успешном техническом результате одиночного случая. Google probe запускается отдельно с разрешённой тестовой таблицей: `python -m scripts.check_google_sheets_live --exercise-failure`. Он добавляет вымышленную строку, поэтому не направляйте его в рабочую таблицу без согласования.

Windows launcher использует доверенный CA bundle certifi при отсутствии заданных оператором SSL_CERT_FILE/SSL_CERT_DIR. Это устраняет обнаруженную ошибку выбора просроченной цепочки в системном хранилище; TLS verification не отключается. Настройка действует только в процессе запуска и восстанавливается на выходе. Если ошибка сертификата остаётся, проверьте дату, доверенную цепочку и операторский CA; не применяйте verify=false.

## Параллельная обработка VK

Long Poll только принимает и распределяет события. `vk_bot/dispatcher.py` запускает обработку в пуле из 16 потоков: отдельная FIFO-очередь на `user_id`, не более одного активного обработчика пользователя. Получение профиля, FSM, ожидание backend/LLM и отправка ответа выполняются внутри обработчика. Поэтому ожидание LLM у одного пользователя не задерживает другого при наличии свободного воркера; сообщения одного пользователя, включая `/reset`, ждут завершения предыдущего события. `/reset` не отменяет уже начавшийся HTTP-запрос.

У рабочих потоков отдельные клиенты VK, не разделяемые с Long Poll. Callback уведомлений задаётся один раз. SQLite-соединение создаётся на каждую операцию; транзакция не удерживается во время LLM. Не запускайте несколько процессов бота для одной группы/базы: FIFO защищает только один процесс; изменения FSM в обход диспетчера требуют отдельной координации.

При Ctrl+C приём прекращается, принятые события обрабатываются до конца. Остановка может ждать сетевых запросов и всей накопленной очереди. Очереди не ограничены по размеру и находятся в памяти: аварийный выход теряет необработанные события, хотя сохранённые согласованные черновики остаются в SQLite. При 16 занятых воркерах остальные пользователи ждут; это не гарантия отзывчивости при любой нагрузке. Для более высокой нагрузки нужны отдельная очередь LLM, лимиты и политика перегрузки.

Регрессии без реального VK/LLM: `python -m unittest discover -s tests -p "test_vk*.py" -v` из активированного проектного venv. Проверяются ответ второго пользователя при заблокированном backend первого, FIFO и завершение очередей, изоляция ошибок, клиенты по потокам и параллельное сохранение черновиков. Полный локальный прогон: `python -m unittest discover -s tests -v`; живую приёмку в группе VK выполняйте отдельно после перезапуска бота.
