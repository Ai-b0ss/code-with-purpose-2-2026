# ГИМ — переносная версия для Ильи (Issue #27)

Уточнение: в новой таблице Евы на 15 строк только 9 кандидатов и 9 карточек ожиданий. Состав целевых 15 анкет нужно сверить по ID. [Разбор](docs/18-criteria-source-audit-20261021.md).

Текущая задача #27/#31 расширена до 15 анкет Ильи. Команда `QA-4-CASES.cmd` по-прежнему прогоняет только четыре встроенных профиля; дополнительные 15 проверяются отдельным набором Ильи через форму или подготовленный им runner. Ева сначала записывает независимые ожидания без ключа, затем сравнивает фактические ответы. [Критерии и ограничения](docs/18-criteria-source-audit-20261021.md).

Это копия актуального сайта и настоящего LLM-backend: новая форма Ильи + DeepSeek через ReformBoss + SQLite. Ни Git, ни GitHub-токенов, ни API-ключей, ни оригинальных анкет ГИМ или приватных исторических данных в ZIP нет.

**Требуется:** Windows, Python 3.11+, интернет для установки Python-зависимостей при первом запуске и для вызова DeepSeek. Это переносной ZIP с исходным Python, не .exe. Git не нужен, три зависимости устанавливаются в локальную .venv.

## Запуск

1. Распаковать архив целиком в папку. Не запускать прямо из окна ZIP.
2. Дважды нажать START-ILYA.cmd. При первом запуске создаст локальную .venv и установит зависимости.
3. Ввести свой API-ключ ReformBoss при запросе. Ключ виден на экране: не делать скриншот. Только сам токен, без Bearer, кавычек и пробелов. Он не записывается на диск.
4. В консоли появится адрес — по умолчанию http://127.0.0.1:8876 (если занят, другой порт). Открыть в браузере на том же ноутбуке. Окно сервера оставить работающим.
5. Заполнить и отправить вымышленную анкету. Бэкенд ждёт живой DeepSeek, сохраняет ответ и показывает заявителю подтверждение. На ответ может потребоваться до 180 секунд.

## Где находится ИИ?

**Заявитель** видит обычную анкету, а после отправки — подтверждение и свой выбор направления. Аналитика для кураторов скрыта от кандидата намеренно.

**Куратор/QA** запускает CURATOR-REPORT.cmd в другом окне: откроется локальный HTML со всеми сохранёнными заявками (из data/gim.sqlite3), включая evaluation_mode, summary, fit_for_museum, fit_for_candidate, possible_problems, interview_questions и дословные evidence.

Это локальный отчёт, не публичный защищённый кабинет. Только синтетические данные; не выкладывать отчёты с реальными ПД. Сервер слушает только 127.0.0.1. Не открывать наружу: нерешённая авторизация и личные данные относятся к Issue #28.

## Как закрыть #27

Запустить QA-4-CASES.cmd в отдельном окне, указать порт работающего сервера. Он:
- убеждается, что GET /api/v1/health сообщает реальный llm и fallback_to_demo=false;
- создаёт четыре уникальные синтетические анкеты CAND-01, CAND-05, CAND-10, CAND-06 из qa/four_cases.json;
- проверяет HTTP 201, созданную запись, пилотный балл 0–3, классификацию полей, непустые evidence и повтор того же ID без дубля;
- сохраняет полный вход и фактический ответ DeepSeek, время, технический статус в reports/issue27_*.json и reports/issue27_*.html.

HTML/JSON передать Еве для содержательного PASS/FAIL. Скрипт НЕ объявляет выводы модели верными: технический PASS не равен экспертному. Синтетические баллы 0–3 не являются исторической калибровкой.

Илья отдельно замеряет ручное заполнение новой формы на ноутбуке и телефоне (цель 5–7 минут; ожидание генерации мерить отдельно). Адрес 127.0.0.1 нельзя открыть с другого устройства: для телефона нужен согласованный безопасный стенд; не публиковать этот локальный API до Issue #28.

Встроенная регрессионная проверка содержит 4 результата: первый курс бакалавриата с индивидуальным графиком, полную занятость при свободных выходных, мультиволонтёрство, сильную магистрантку. Проверить риски/исключения, релевантность направления и вопросов, отсутствие выдуманных фактов и соответствие evidence анкетам. Ни один фактор автоматически не означает отказ.

Итог: загрузить синтетические JSON/HTML, оценку Евы и UX-замеры в https://github.com/Ai-b0ss/code-with-purpose-2-2026/issues/27. Закрыть Issue только после экспертной приёмки.

## Файлы

START-ILYA.cmd — создаёт локальное Python окружение и запускает приложение в LLM-режиме.

QA-4-CASES.cmd — запускает четыре настоящие LLM-проверки через локальный API.

CURATOR-REPORT.cmd — показывает внутреннюю аналитику из локальной SQLite в браузере.

frontend/index.html — последний публичный интерфейс Ильи.

backend/app.py — FastAPI, API, SQLite и вызов оценщика.

backend/evaluator.py и backend/evaluation_harness.py — ReformBoss, классификация полей, граф знаний, проверка цитат и серверный пилотный расчёт балла.

docs/08-synthetic-candidates.md — исходные синтетические профили. qa/four_cases.json — их четыре структурированных QA-варианта.

reports и data создаются только после работы, в ZIP отсутствуют.

## Исправление ошибки evaluator_invalid_model_json

В обновлённой сборке исправлена совместимость точных evidence DeepSeek: числа, boolean и списки преобразуются в строки только после проверки полного совпадения с анкетой. Пустые источники не считаются доказательствами. Числовой балл теперь рассчитывает сервер после классификации полей; при содержательной браковке он остаётся `null`.

Если скачали первую версию ZIP и видите эту ошибку: замените backend/evaluator.py и frontend/index.html файлами из обновлённой сборки, перезапустите START-ILYA.cmd с ключом, затем повторите отправку. Не удаляйте папки data/reports и браузерный черновик. Подробности: docs/16-deepseek-evidence-fix-20261021.md в репозитории.
