# Музейный компас — тестовая сборка команды с пилотной оценкой (22.10.2026)

Это **переносной ZIP, не exe и не публичный сервис**. Windows 10/11 и Python 3.11+ обязательны. Git, GitHub-токен, права администратора не нужны. Интернет нужен для первой установки Python-пакетов и облачных запросов через ReformBoss; при настроенной локальной модели предусмотрен резервный переход на неё.

## Запуск

1. Распаковать ZIP целиком в свою папку, не запускать напрямую из архива.
2. Дважды нажать **START-TEAM.cmd** (или запустить `powershell -NoProfile -ExecutionPolicy Bypass -File .\team-start.ps1`). Первый запуск создаёт локальную `.venv` и скачивает зависимости.
3. Дождаться запроса ключа; **ввести ReformBoss API-ключ** без префикса Bearer. Ввод **видимый**, поэтому не включать запись экрана и не отправлять скриншоты консоли. Ключ не записывается в файл. Он находится в переменных окружения процесса и очищается при завершении команды.
4. В консоли появится `http://127.0.0.1:8876` (при занятом порте ближайший свободный). Открыть его в браузере **того же ноутбука**, не закрывая консоль. Открывать через интернет/туннель пока запрещено.
5. Заполнить **вымышленную** исходную анкету. При переходе на шаг 4 модель сначала изучит 5 критериев и при существенной неопределённости задаст **0–2 вопроса самому кандидату**. Ответьте на них (допустимо «Пока не знаю»); только затем нажмите «Отправить». Классификация полей и заключение выполняют несколько обращений к модели; переключение между моделями может увеличить время и расход лимита провайдера. Остановка сервера — Ctrl+C.

При запуске **нет предварительного платного LLM-пробника**. В /api/v1/health должно быть `evaluation_mode=llm`, `fallback_to_demo=false`; это проверка конфигурации, **не доказательство доступности модели**. Настоящая проверка — успешная отправка вымышленной анкеты с `evaluation_mode=llm` и непустыми `evidence`.

## Что смотреть

- **Форма**: четыре шага, в настоящем LLM-режиме **0–2 вопроса по выявленным пробелам**, заданные ДО отправки; отсутствие пробелов означает 0 вопросов. В `rules_demo` остаются прежние правила (до 3 вопросов). Выбранное направление сохраняется.
- **Оценщик**: повторно учитывает ответы на уточнения, даёт оценки по 5 критериям, `preliminary_verdict`, `verdict_comment`, сильные стороны, риски, рекомендуемое направление. **Вместо лишнего списка вопросов для будущего собеседования модель обязана задавать их ДО заключения**. `CURATOR-REPORT.cmd` показывает вопросы, ответы и результаты из локальной SQLite.
- **Пилотная оценка 0–3**: модель классифицирует ответы по полям; сервер воспроизводимо рассчитывает пять уровней `scorecard` и предварительный `score` из категорий и явных данных о нагрузке. Направленное оскорбление останавливает оценку (`score=null`); бессмыслица сильно снижает балл и требует ручной проверки. Медианная поправка из исторических полей отключена до проверки меток куратором. **Это не подтверждённая кураторами шкала и не решение о приёме**. В `rules_demo` балла нет.
- **QA-4-CASES.cmd**: четыре встроенных синтетических сценария. **Каждый вызовет реальный LLM API** и может расходовать лимиты/деньги. Проще начать с одной анкеты, а потом запускать полный QA.
- **Сохранение**: SQLite хранит запись и статус синхронизации. При настройке ID таблицы и сервисного аккаунта заявка пишется в Google Sheets; повтор ID не создаёт строку заново, ошибку доставки можно повторить через `/api/v1/applications/{id}/sync`. CSV доступен только как дополнительный экспорт.

## Ограничения и защита

Это локальная тестовая версия **только для синтетических данных**. API списка анкет, карточек и экспорта **не закрыт авторизацией** (#28). Не открывать сервер на 0.0.0.0 и не публиковать через туннель. Устанавливать только на доверенных ноутбуках. При передаче ZIP проверить SHA256 в GitHub/манифесте и не добавлять приватные анкеты/ключи.

Новый ZIP собран из текущего рабочего дерева с обновлённой двухэтапной логикой оценки, включая ограничение вопросов и атомарный ID. Папки `data`, `reports`, история Git, приватные таблицы, DOCX, API-ключи, `.env` и `.venv` не включаются. Документы требований внутри архива — только текстовые файлы; исходные материалы и экспертные таблицы доступны ответственным участникам отдельно.

**Проверки проекта:** pytest, локальный FastAPI smoke и облачная проверка API на вымышленных анкетах. Подробности в `docs/23-evaluation-harness-20261022.md`. Технический PASS не заменяет экспертную оценку Евы и утверждение числовой рубрики 0–3.

Документы: `docs/04-gim-requirements.md`, `docs/06-gim-stakeholder-answers.md`, `docs/20-gim-scoring-pilot-20261022.md`, `docs/21-ai-clarification-before-verdict-20261022.md`, `docs/23-evaluation-harness-20261022.md`. Поставка ZIP должна собираться из текущего дерева после проверки.

## Если не запускается

Python не найден или версия ниже 3.11 → установить Python 3.11+ и запустить снова. Ошибка pip → проверить доступ к PyPI. TLS/network preflight → проверить сеть, ключ ещё не запрашивался. HTTP 401 → ключ неверный/не принимается. HTTP 429 → лимит провайдера. 503/timeout → ответ LLM не получен за таймаут. Порт занят → скрипт выберет другой из 8876–8896. Данные `data/` не стирать при повторном запуске.
