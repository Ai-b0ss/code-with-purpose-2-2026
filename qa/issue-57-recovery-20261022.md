- Нет внешних запросов к модели, VK или Google.

## Неподтверждённые сценарии и статус #57

- **T37 — PARTIAL:** сохранение и повтор локальной SQLite подтверждены; настоящая доставка Google, ambiguous append/timeout, живой VK Long Poll и падение под реальной нагрузкой не проверены на актуальном SHA. Результат фактического Google может отличаться от controlled mock.
- **T38 — PARTIAL/PASS для demo:** новый Windows запуск из ZIP и штатный локальный продуктовый путь подтверждены; запуск реальной цепочки VK → DeepSeek → SQLite → Google на этой же версии не подтверждён.
- Обработка `application_reservations` защищает от дубля сохранённого ID, но **не гарантирует exactly-once LLM billing** после аварии; она остаётся ограничением API провайдера.
- FIFO VK-диспетчера — в памяти одного процесса, необработанные события могут потеряться при аварийной остановке; session SQLite и повтор от кандидата компенсируют это лишь частично.
- При одновременном восстановлении после длинного Google timeout и истечении 180-секундной lease абсолютная гарантия единственной Google-строки между независимыми процессами не доказана; необходим контролируемый live-тест и/или отдельное согласованное решение о сериализации.
- Для публикации анкеты с реальными ПД отдельно требуется закрытие security/privacy gate #28.

**Вывод:** новый локальный demo-релиз проверен гораздо шире, но issue #57 не закрывается до точной live-проверки VK/LLM/Google и окончательной release-приёмки по #9/#60. Не переносить PASS старых live-прогонов на новый commit.
