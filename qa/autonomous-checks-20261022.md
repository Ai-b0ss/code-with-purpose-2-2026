# Дополнительная автономная проверка — 22.10.2026

База: main `56f051c01b2f7a5db2443733b9b5f977b346bb2a` после PR #58. Изменённые файлы закреплены в `qa/autonomous-source-sha256.txt`; окончательный commit и SHA256 ZIP указаны в PR. Все новые входы вымышленные. Рабочий сервер пользователя и реальные анкеты не изменялись.

## Найдено и исправлено

1. Web сбрасывал ID на любом input/change, даже при повторном вводе прежнего ответа. После сохранения на сервере и потери подтверждения это позволяло создать дубль. Теперь сравнивается содержимое анкеты без ID: неизменившийся ответ сохраняет ID; содержательное изменение начинает новую отправку. Кнопки часов и дней проходят тот же обработчик и сбрасывают устаревшие ИИ-уточнения при изменении исходного графика.
2. Python 3.13 на подключённом Windows отклонял цепочку TLS ReformBoss (`certificate has expired`, verify code 10), хотя Schannel/curl получал 401. Проверка с certifi подтвердила HTTPS/401. Launcher теперь выбирает certifi через SSL_CERT_FILE, если оператор не задал SSL_CERT_FILE/SSL_CERT_DIR, и восстанавливает окружение после выхода. Проверки сертификата/имени хоста остаются включены. certifi объявлен прямой зависимостью. Настройки Windows и глобальные сертификаты не менялись.
3. Live-сценарии содержали анкеты без новых обязательных полей, а Google probe ожидал внутренний sheet_sync в публичном подтверждении. Исправлены 24 синтетических сценария и Google probe. Четыре экспертных входа не изменены: runner явно строит производный набор `four-cases-mandatory-v2` и помечает версию в отчёте. Добавление административных полей не считается новым одобрением Евы.
4. Live runner проверяет защищённое сохранённое заключение, повтор без дубля и отсутствие evaluation в публичных ответах. HTTP 201 без результата/авторизации больше не считается техническим PASS. Добавлены выбор сценариев, число потоков, проверка локального URL и доступа координатора; отчёты v3 сохраняются в отдельные каталоги.

Recovery probe поднимает настоящий Uvicorn и отдельный HTTP-провайдер на свободных localhost-портах. Проверены HTTP 401/429/503, неправильный envelope, два неверных JSON, timeout и запрет redirect: клиент получает безопасный 503 без тела провайдера, анкета не сохраняется, резерв освобождается. Одновременные повторы вызывают провайдера один раз. После рестарта сохранённая оценка возвращается без нового вызова. После принудительного kill до commit резерв восстановлен через штатный механизм: время started_at сдвинуто на 601 секунду вместо ожидания десяти минут; сохранена одна итоговая запись. Не утверждается exactly-once вызов внешней модели после аварии. Идентифицирующие поля не попадали ни в один запрос провайдеру.
