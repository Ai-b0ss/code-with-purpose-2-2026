## Контракт и оставшаяся проверка

- Фикстуры воспроизводят все T09–T19 и T21. Все 16 локальных HTTP запросов получили 200 и не более двух вопросов в первом раунде. Тесты отдельно покрывают 0 вопросов при полном профиле **когда модель вернула `clear`**, второй раунд не более одного вопроса, ответ «Пока не знаю», сохранение `followup_answers.ai_availability` в итоговом `scorecard`, 503 без скрытого перехода на demo, веб-черновик и VK FSM с вымышленными данными. Это проверки контракта, а не доказательство релевантности новой модели.
- Для содержательной оценки каждого вопроса нужно предъявить пять `criteria_review`, точный пробел в полях анкеты, текст ответа, который изменит рекомендацию (`decision_impact`), и подтверждённый источник каждого утверждения о музее. Рецензент отмечает: **релевантен / уже отвечено / повтор / неподтверждённый факт / дискриминационное допущение**. При «Пока не знаю» остаточный пробел остаётся куратору; не возникает автоматический отказ. Не следует использовать длину мотивации как единственную меру качества.
- `qa/expert-gim-acceptance.md` (#27) относится к **итоговым рекомендациям**, а не к предварительным уточнениям. Комментарий к #49 о живом случае `collections` сообщает один релевантный пример, но не содержит полного сырого набора по направлениям. Поэтому содержательная оценка Евы и фактические новые ответы DeepSeek для T09–T19/T21 по-прежнему `NOT_RUN`; issue остаётся открытым.
- `llm_trying` исследована. Полезная идея ветки — связывать предлагаемый вопрос с полем анкеты и проверенным фактом. Её большой граф знаний и набор регулярных выражений не переносились: это отдельная экспериментальная архитектура и потенциально RAG #32. В работающий агент не добавлены новые проверки по ключевым словам или часам фондов. Для спорного случая нужна оценка по фактам моделью и куратором, а не список запрещённых фраз.
